# local-inference-lab/b12x (CUDA, SM120) — what transfers (sub-agent report 2026-08-28, condensed)

Kernel library (CuTe DSL + Triton, no C++), consumer Blackwell only; covers Qwen3.8-27B and
Qwen3.8-Flash-Next ops (QSA, GDN decode, PLE, hyper-connections, MTP feedback) but publishes no
Qwen3.8 measurements. Its end-to-end serving efficiency is low (~35% of HBM on a 27B); the ideas
are worth more than its numbers.

## Transferable (verified in their code)
- **GQA group packed into the MMA M rows** for attention: q_len × 6 heads as rows so each K/V
  tile is read once per kv head; per-row causal limit. For our 24q/4kv × 256: bare decode = 6
  rows of a 16-row WMMA tile (bandwidth-bound anyway), MTP T=8 → 48 rows. Never one block per
  q-head (their own QSA core does that and re-reads K/V 12×).
- **Split-KV for decode** (fp32 partial O + base-2 LSE merge): their MLA postmortem measured
  3.2–4.1× from wave-balanced splits; "num_splits=1 starves the GPU". With 4 kv heads on 40 CUs
  we need ≥10 splits per kv head.
- **Inline dequant into the WMMA B fragments for prefill** (their W4A16 path): kills the
  materialised bf16 pass (our dequant = 54 GB written per chunk ≈ 10% at T=2048, 29% at 512).
  Tile lesson: M-independent (64,128) beat (128,128) at every M on a 188-SM part; plan 64×128 /
  64×64 tiles with 2–3 VGPR-staged stages on 40 CUs / 64 KB LDS.
- Int8 activations + int8-unpacked K-quants with per-32-block scales in the epilogue (2 WMMA per
  block then 1 FMA per accumulator ≈ 3% overhead) — *but on gfx1151 iu8 = bf16 rate*, so the win
  is bandwidth/scratch, not math. Gate on KLD.
- Fusing the ~12 per-linear activation-quant launches saved 1.7 ms/token on a 27B (their
  measurement) — same class as our launch-count loss.
- Graph-capture discipline: no live quantities in kernel selection; runtime scalars in device
  memory; static capacity grids with early-exit masks; metadata regenerated on-device; Int64
  offsets; precompile+warm every m before capture.
- GDN decode mapping = ours (32 value-rows × 8 lanes, 16 fp32 state elements per thread);
  β rounded through bf16 and bf16-rounded normalised output to match HF bit-for-bit; bf16 state
  accepted at rtol 1e-2 (halves the 6 MiB/layer state traffic).
- QSA selection pipeline for Flash-Next: mean-pool-4 index keys → Gemma RMSNorm → RoPE at group
  start; score Σ_h ReLU(q_h·k) over 4 index heads; radix top-512 groups with ascending-id tie
  break; raw ring with int64 logical-position tags so rejected drafts need no rollback.
- MoE decode: direct top-k (no sort) for m ≤ 8; persistent cooperative kernel, one CTA per CU,
  FC1→SiLU→FC2 with software grid barriers; K-split small experts 4–8× at m ∈ {1,2} because a
  single serial chain leaves the grid idle.
- Greedy argmax as one u64 max: (f32→u32 order key << 32) | ~index.

## Not portable / not worth it
FP8/FP6/FP4 block-scaled MMA, TMA/mbarrier pipelines, cp.async, ldmatrix, trellis (QTIP) weights,
MLA/DSA/GLM/Kimi paths, 99 KB smem tiles, their 188-SM occupancy ladders.
